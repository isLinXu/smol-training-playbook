# 模型架构设计

架构决策是模型性能的基础。让我们基于 SmolLM3 训练的经验证据来探索关键选择。

## 注意力机制

### KV-Cache 方法对比

| 机制 | KV-Cache 参数/Token | 特点 |
|------|-------------------|------|
| MHA (多头注意力) | 2×nheads×nlayers×dimhead | 全容量，最占内存 |
| MQA (多查询注意力) | 2×1×nlayers×dimhead | 共享 KV，节省内存 |
| GQA (分组查询注意力) | 2×g×nlayers×dimhead | 平衡之选 (推荐) |
| MLA (多潜在注意力) | 4.5×nlayers×dimhead | 潜在压缩，DeepSeek |

### 关键发现

> GQA（比率 2-8）是 MHA 的可靠替代，在显著降低 KV-Cache 的同时保持性能。

**SmolLM3 采用 GQA，比率 4。**

## 文档级掩码 (Intra-Document Masking)

### 问题

在打包序列中，token 可能关注不相关的文档。

### 解决方案

修改注意力掩码，限制 token 只能关注同一文档内的前序 token。

### 发现

- 短上下文任务无明显影响
- 在扩展到长上下文时至关重要
- **SmolLM3 全程采用此技术**

## 嵌入共享

### 核心机制

- 输入嵌入和输出嵌入复用同一矩阵
- 节省约 **18%** 的参数量

### 发现

- 1.2B 共享嵌入模型 ≈ 1.46B 非共享版本
- 在相同参数预算下，增加深度优于取消嵌入共享
- **SmolLM3 保留共享嵌入**

## 位置编码与长上下文

### 位置编码演进

```
绝对位置编码(APE) → 相对位置编码 → ALiBi → RoPE → NoPE
```

### RoPE 核心思想

- 将位置编码为高维空间中的旋转角度
- 点积自动编码相对距离，自然支持外推

### RoPE 频率调整方法

| 方法 | 描述 |
|------|------|
| **ABF** | 统一提高基准频率（如 10K→1M） |
| **YaRN** | 不同维度不同缩放，更平滑 |

### NoPE（无位置编码）

- 通过因果掩码隐式学习位置
- 在长度泛化上优于 RoPE
- 短上下文略弱于 RoPE

### RNoPE 混合方案（Llama4、SmolLM3 采用）

- 层间交替 RoPE 和 NoPE
- RoPE 提供显式位置信息
- NoPE 提升远距离检索

## 注意力范围限制方法

| 方法 | 描述 | 采用模型 |
|------|------|---------|
| 分块注意力 | 固定块大小，硬边界 | Llama4 |
| 滑动窗口 | 最近 N 个 token 连续覆盖 | Mistral, Gemma3 |
| DCA (双块注意力) | 跨块信息流，无需训练 | Qwen2.5 1M 上下文 |
| Attention Sinks | 初始 token 作为汇聚点 | 多种模型 |

## 稳定性提升

| 技术 | 作用 | SmolLM3 采用 |
|------|------|-------------|
| Z-loss | 防止 logits 过大 | ❌（有开销） |
| 嵌入层无权重衰减 | 防止梯度放大 | ✅ |
| QK-norm | 归一化 Q/K 向量 | ❌（伤长上下文） |

## 混合专家 (MoE)

### 核心思想

每个 token 只路由到少数专家。

### 关键设计参数

| 参数 | 描述 | 经验结论 |
|------|------|---------|
| **稀疏度** | 专家总数/激活数 | 更高更好，但收益递减 |
| **粒度** | expert 越小→专家越多 | 存在甜点区间 |
| **共享专家** | 始终激活的专家 | 1个共享专家通常最优 |

### 负载均衡

- **问题**：避免路由坍缩到少数专家
- **方法**：辅助损失 或 无损均衡（DeepSeek V3 的偏置调整法）

## To MoE or Not To MoE

| 场景 | 推荐架构 | 原因 |
|------|---------|------|
| 内存受限/新手 | Dense | 生态成熟，稳定 |
| 追求单位算力最优 | MoE | 训练推理效率高 |
| 超长上下文+降推理开销 | Hybrid | SSM 处理长序列 |

**SmolLM3 选择 Dense**（端侧部署、3个月时间框、团队经验）

## 分词器

### 核心指标

| 指标 | 定义 | 越低越好 |
|------|------|---------|
| **Fertility** | 平均每个词所需 token 数 | ✅ |
| **续分词比例** | 被拆分的词占比 | ✅ |

### 选择原则

- 英语模型：~50k 词表
- 多语言模型：100k+（如 Llama3 的 128k）
- 根据目标语言 fertility 选择

**SmolLM3 选择 Llama3.2 分词器**（多语言效率最佳折中）

## SmolLM3 最终架构

| 参数 | 值 |
|------|---|
| 参数量 | 3B |
| 架构 | Dense Llama-style |
| 注意力 | GQA（比率 4） |
| 位置编码 | NoPE + 文档掩码 |
| 嵌入 | 共享 + 无权重衰减 |
| 分词器 | Llama3.2 |
| 最大上下文 | 128k |
