# 小型消融实验

> "所有伟大的模型都始于小型消融实验。"

消融研究是可靠语言模型训练的基石。它让你在投入昂贵的生产训练之前，以低成本验证想法。

## 为什么消融实验很重要

机器学习是**实验科学**，而非纯数学。我们的直觉经常失灵：

- 来自 arXiv 的高质量数据可能反而**损害**小模型性能
- 看似有益的架构更改可能无法规模化
- 在小规模上最优的超参数可能无法迁移

## 两个关键属性

每个消融研究都必须平衡：

| 属性 | 描述 | 目标 |
|------|------|------|
| **速度** | 你能多快地迭代？ | 频繁运行实验 |
| **可靠性** | 你能相信结果吗？ | 低噪声、强信号 |

## 消融金字塔

```
        ▲
       /│\        大规模 (昂贵)
      / │ \       完整生产运行
     /  │  \
    /───┼──-\      中等规模
    │   │   │
    │   │   │      小规模 (便宜)
    │   │   │
    └────────┘     极小规模 (快速)
```

**始终从底部开始，逐步向上推进。**

## 选择基准

### 好的参考架构应具备：

- ✅ 符合部署需求
- ✅ 经过大规模验证（数万亿 tokens）
- ✅ 文档齐全
- ✅ 框架支持良好

### 主流架构选项 (2025)

| 架构类型 | 模型系列 | 参数量 |
|---------|---------|--------|
| Dense | Llama 3.1/3.2 | 8B, 70B / 1B, 3B |
| Dense | Qwen3 | 0.6B-32B |
| MoE | Qwen3 MoE | 30B-A3B, 235B-A22B |
| MoE | Kimi K2 | 1T-A32B |
| Hybrid | Falcon-H1 | 0.5B-34B |

## 降低基准风险

> **准则**：除非测试证明某项更改确实有用，否则不要改动任何内容。

### 如何降低风险：

1. **一次只测试一项更改**
2. **将成功的更改集成到新基准后再测下一项**
3. **避免详尽的网格搜索**

### 消融配置示例 (1B Transformer)：

```yaml
# 架构: Llama3.2 1B 配置
layers: 16
hidden_size: 2048

# 数据混合
- FineWeb-Edu: 70%
- Stack-Edu-Python: 20%
- FineMath: 10%

# 优化器
optimizer: AdamW
peak_lr: 5e-4
scheduler: cosine

# 规模
gpus: 8
tokens: 30B
```

## 评估：获取可靠信号

### 可靠评估的四个原则

| 原则 | 描述 |
|------|------|
| **单调性** | 分数随训练稳步提高 |
| **低噪声** | 在不同随机种子下稳定 |
| **高于随机** | 不要使用仅在训练后期才显现信号的任务 |
| **排名相关性** | 早期优胜者应保持优势 |

### 任务形式对比

| 形式 | 描述 | 适用于 |
|------|------|--------|
| 多项选择 (MCF) | 在提示中包含 A/B/C/D 选项 | 主训练运行 |
| 完形填空 (CF) | 比较似然度，无需提示 | 早期消融 |
| 自由生成 (FG) | 贪婪解码准确性 | 后训练 |

### 标准评估套件

```
MMLU      - 知识
ARC       - 推理
HellaSwag - 常识
GSM8K     - 数学
HumanEval - 代码
RULER     - 长上下文
```

## 成本分析

| 阶段 | GPU | 天数 | GPU 小时 |
|------|-----|------|---------|
| 主预训练 | 384 | 302 | 276,480 |
| 消融实验 | 192 | 156 | 69,120 |
| 调试/恢复 | 384/192 | 3/4 | 46,080 |
| **总计** | — | — | **437,760** |

> ⚠️ 消融成本占总算力的 **37%** —— 必须纳入预算！

## 关键要点

1. **先验证后规模化** —— 永远不要先做大实验
2. **一次只测一个变化** —— 集成测试优于网格搜索
3. **测量一切** —— 无法测量的就无法改进
4. **为消融做预算** —— 它不是可选的
